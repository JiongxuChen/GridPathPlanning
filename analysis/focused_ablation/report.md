# T5-base 聚焦消融与失败分析

## 范围与来源

- 主复现和消融运行于不同的远端隔离副本；
  消融不覆盖主复现检查点。
- 消融仅移除逐步验证器合法前缀的损失项，决定位置保留原先的类别权重
  和系数；输入、模型、优化器、数据流、seed 42、750 次更新、三遍末权重、
  G 和四条修复路线均不变。10 步 pilot 已包含在 750 步内。
- 消融仅在开发集 G60/V80/R60 上评价。两个既有测试集已经公开且被查看，
  本次不对消融运行测试，不能宣称未见测试泛化或统计显著性。
- `compare_dev.py` 检查训练绑定除 `planning/model.py` 哈希外一致；
  源码 AST 除模块文档和 `path_loss` 外一致；120 条 G/R 案例的初始生成、
  真值和两条执行器路线逐例一致；80 条固定 V 案例真值一致。
  两次开发 CPU 重放复核均为 `passed`。

## 聚焦消融结果

| 开发集指标 | 完整逐步 V | 去合法前缀损失 |
| --- | ---: | ---: |
| 固定 V80 Macro-F1 | 0.9499 | 0.3333 |
| 有效路径正确判定 | 40/40 | 0/40 |
| 无效路径正确判定 | 36/40 | 40/40 |
| 首错定位 | 34/40 | 8/40 |
| 碰撞联合诊断 | 4/10 | 2/10 |
| 晚首错定位，step > 1 | 28/32 | 0/32 |
| 自然 G60 模型提示最终成功 | 43/60，调用 6 次 | 43/60，调用 60 次 |
| 自然 G60 模型前缀最终成功 | 42/60，调用 5 次 | 42/60，调用 60 次 |
| 受控 R60 模型提示修复 | 33/60，调用 54 次 | 35/60，调用 60 次 |
| 受控 R60 模型前缀修复 | 29/60，调用 47 次 | 39/60，调用 60 次 |

去前缀监督后，80 条固定 V 样本**全部预测为 invalid 且都定位在第 1 步**，
其中 70 条预测为碰撞。虽然自然 G 的碰撞检出从 5/17 表面升至 17/17，
但这是全报错的结果，不能算碰撞识别改善。R60 修复率上升也伴随近乎
无条件的 G 调用；自然 G 成功数没有增加，调用却由 6/5 次分别涨到 60 次。
本单 seed、开发集消融支持的结论是：在当前训练设置下，合法前缀监督是
避免第 1 步恒定报错和维持有效路径特异性的关键组成；不证明它在其他
seed、模型或新数据上必然产生同等幅度的效果。

额外 GPU wall time 为 **0.1187 小时**，包含 pilot、正式训练和开发评价；
消融副本继承主复现约 0.9519 小时账本，总计约 1.0706 小时。

## 完整方法的失败归因

独立固定 V80 与自然 G60 不可混作同一分布。以下测试 ID/OOD 的 G60
是同一批生成问题与输出，**不当作两组独立的自然生成证据**。

| 逐例分组 | 开发 | 单错测试 |
| --- | ---: | ---: |
| 自然 G 原失败 | 18/60 | 13/60 |
| 其中碰撞 | 17/18 | 11/13 |
| 完整 V 检出自然碰撞 | 5/17 | 3/11 |
| 完整 V 联合诊断正确的自然碰撞 | 3/17 | 1/11 |
| 位移终点看似到目标的自然碰撞 | 15/17 | 9/11 |
| 其中被完整 V 检出 | 3/15 | 1/9 |
| 正确执行器反馈下提示修好原失败 | 1/18 | 0/13 |
| 正确执行器反馈下前缀修好原失败 | 0/18 | 1/13 |
| 正确反馈提示调用后原样重复失败路径 | 15/18 | 10/13 |

固定 V80 的开发碰撞联合诊断为 4/10，单错为 2/10；单错其余三类
越界、非法词、未到目标各为 10/10。自然 G 的碰撞多数有正确的
未检查位移终点，提示模型可能利用了终点捷径；这是待进一步
干预验证的机制假设，不是已证实的因果解释。
执行器反馈是正确的诊断对照，不代表 G 必然会利用它；上述重复路径
与低修复数证明此轮端到端瓶颈同时在 V 的空间漏判和 G 的反馈响应。

可复查单错样本 `sample_9f8eb13c8482beedaec0f2ef`：`up up up right`
在第 2 步撞上 (1,4)，未经合法性检查的位移终点却为目标 (0,5)。
完整 V 判 `valid`，模型反馈不触发；执行器给出正确首错后，
提示和前缀仍输出原失败路径。
