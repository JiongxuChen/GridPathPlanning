# 局部占据 V：冻结鲁棒性与历史总体评价

## 评价身份

先写定 [鲁棒性协议](robustness_v1.md)，再以 seed 20261116
冻结 132 条新候选；挑战 JSON SHA256 为
`038d64a6343ca31104f09b4206ab466d5b6db12c2e02d7e98fc797b570183e9c`。
新布局与训练、开发、已公开 ID/OOD 及上一轮新布局挑战均不重叠。
两版 V 使用相同候选；局部 V 的 checkpoint、输入表示、2048-token
上限均未调整。执行器只用于离线构造、真值及评分，V 推理不调用执行器。
这是看过开发结果后设计的定向 OOD 扩展，不能称为项目最初封存的盲测。

## 新布局鲁棒性

下表的联合正确仅以真实无效候选为分母；有效组报告正确保留。
接口拒绝仍计入原始组分母，未删除样本。

| 组别 | 原结构化 V | 局部占据 V |
| --- | ---: | ---: |
| 6×6 长有效路径，正确保留 | 20/20 | 20/20 |
| 6×6 晚碰撞，检出 | 7/20 | 20/20 |
| 6×6 晚碰撞，首错与类型联合 | 7/20 | 15/20 |

| 10×10，分类／碰撞联合 | 11/20、0/10 | 20/20、10/10 |
| 长度边界，有效路径正确保留 | 4/12 | 6/12 |
| 长度边界，接口拒绝 | 8/12 | 6/12 |

晚碰撞五次失败均诊断为碰撞，但首错位置比执行器早一步；
不是漏检或类型错误。双事件组中每个事件单独都无效且原路径索引
不同，但执行器遇首错就停，因此这组只检验**首次**错误，
没有证明模型能分别识别第二个错误。

长度边界组覆盖 16、约 24、32、48、64、72 动作；局部 V 对
16、25、32/33 动作均成功预测，对 49、64/65、72 动作的六条
有效路径因源输入超过 2048 token 而拒绝。这是可用范围限制，
不能把“已拒绝”解释为有效性判断正确。密集 8×8 的原 V 另有
3/20 次源输入拒绝，局部 V 为 0/20。

## 已公开 ID/OOD 历史配对

鲁棒性评价之后，才运行此前已经公开并曾用于项目分析的固定
ID/OOD 面板。两版共用 G、执行器、候选、四条单次修复路径；
逐例核对了初始 G 输出及执行器反馈路径完全一致。
**这些数字不是新的盲测结果，也未用于本轮挑选表示。**

## 结论与限制

按预先写定的判据，局部占据 V 可以锁定为当前验证器候选：
长路径没有新增误报，晚首错和双事件优于原 V，8×8/10×10
定向挑战有完整覆盖。尚不能宣称一般化证明：仅一个训练 seed，
新布局组规模小、错误类型集中于碰撞，晚碰撞仍有 5/20
定位偏差，长输入存在明确拒绝。输入中心占据状态是强几何
特征工程，而非模型从原始文本独立发现规则。
